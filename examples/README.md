# Real-World Examples

This directory contains complete, production-ready examples showing Better-PromptKit in action across different technology stacks and project types.

---

## Example Projects

### 1. **SaaS Dashboard** (Next.js + Supabase + Drizzle)
A multi-tenant B2B analytics dashboard with team workspaces, role-based access control, and real-time collaboration.

- **Stack**: Next.js 15, TypeScript, Supabase Auth, Drizzle ORM, Tailwind v4, tRPC
- **See**: `saas-dashboard/`
- **Highlights**: 
  - Complete STATE.md tracking feature development
  - PROMPTKIT.md with monorepo workspace configuration
  - Real ADRs from architecture decisions
  - Before/after code review examples

### 2. **E-Commerce API** (Node.js + PostgreSQL)
RESTful API for product catalog, cart management, and order processing with payment integration.

- **Stack**: Node.js, Express, PostgreSQL, Prisma, Stripe
- **See**: `ecommerce-api/`
- **Highlights**:
  - Data schema evolution using Expand-Contract pattern
  - API contract specifications
  - Performance optimization examples
  - RCA post-mortem from production incident

### 3. **Mobile-First Landing Page** (Astro + Tailwind)
Marketing website with accessibility compliance and performance optimization.

- **Stack**: Astro, TypeScript, Tailwind CSS, WCAG 2.2 AA
- **See**: `landing-page/`
- **Highlights**:
  - Complete DESIGN.md with anti-slop rules
  - Design token specifications
  - Accessibility audit results
  - Core Web Vitals optimization

### 4. **CLI Tool** (Rust)
Developer productivity CLI with configuration management and plugin system.

- **Stack**: Rust, Clap, Tokio
- **See**: `cli-tool/`
- **Highlights**:
  - Technical spike comparing async runtimes
  - Debug workflow catching race condition
  - Integration test strategy
  - Release checklist example

## How to Use These Examples

### For Learning
1. Browse the examples to see PromptKit workflows in realistic contexts
2. Study the conversation patterns and workflow progressions
3. Adapt patterns to your own projects

### For Onboarding
1. Use examples as templates when running `pk:onboard`
2. Copy relevant sections to your project's documentation
3. Customize based on your stack and team preferences

### For Reference
1. Check examples when unsure how to structure artifacts
2. Compare your workflow usage against production patterns
3. Learn from real debugging and optimization sessions

## What's Included in Each Example

Each example directory contains:

### Core Configuration
- `PROMPTKIT.md` - Project profile with stack constraints
- `DESIGN.md` - Visual identity and brand rules (when applicable)
- `docs/STATE.md` - Living project tracker showing progression

### Artifacts
- `docs/specs/*.md` - Technical specifications from pk:plan
- `docs/adrs/*.md` - Architectural decisions from pk:retro
- `docs/data/*.md` - Database schemas from pk:data
- `docs/auth/*.md` - Auth matrices from pk:auth
- `docs/api/*.md` - API contracts from pk:api
- `docs/tests/*.md` - Test strategies from pk:test
- `docs/perf/*.md` - Performance audits from pk:perf
- `docs/rca/*.md` - Post-mortems from pk:debug

### Conversations
- `conversations/*.md` - Annotated AI conversation transcripts showing:
  - Initial planning sessions
  - Debugging investigations
  - Code review discussions
  - Learning sessions with pk:tutor

## Contributing Examples

Have a great PromptKit success story? We'd love to see it!

**Requirements**:
- Real project (sanitize sensitive data)
- Demonstrates at least 3 different workflows
- Includes before/after code or metrics when applicable
- Shows actual artifacts generated by workflows

**How to Contribute**:
1. Create a new directory under `examples/`
2. Include README.md explaining the project context
3. Add relevant artifacts and conversation excerpts
4. Sanitize any proprietary or sensitive information
5. Submit a PR to the main repository
