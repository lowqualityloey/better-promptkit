## Overview

Better-PromptKit v1.0.0 is proposed as the first release of the repository's instruction-layer engineering system for AI coding assistants. It provides Git-tracked workflows, protocols, templates, initialization scripts, and adoption documentation without installing a runtime, CLI binary, or package dependency.

## Included surface

- 19 workflow files covering routing, planning, onboarding, tasks, data, authentication, API contracts, testing, design, research, debugging, performance, review, commits, pull requests, shipping, checkpoints, and retrospectives.
- Named `pk:` triggers and aliases for routing and activating those workflows.
- 4 operating protocols for setup, context synchronization, quality gates, and subagent delegation.
- 17 templates for project profiles, design systems, state tracking, specifications, tests, releases, pull requests, reviews, performance, incidents, and technical spikes.
- Cross-platform `init.sh` and `init.ps1` setup that creates the standard documentation directories, scaffolds `PROMPTKIT.md` and `docs/STATE.md`, and maintains an idempotent agent-directive block.
- Adoption, workflow-map, FAQ, and token-efficiency documentation for new and existing projects.
- A corrective PowerShell interpolation fix in `scripts/validate-references.ps1` from ancestor commit `0e83dbefeb6958bb5063185de8c0747b3cf9ec5a`.

Agent Execution Control is not implemented in this release. The tracked requirements file is planning content only.

## Compatibility and upgrade guidance

No application, runtime, database, dependency, or production-deployment migration is required for this instruction-layer release.

For a Git submodule installation, update the submodule and rerun the platform initialization script. For a direct clone, pull the repository and rerun `init.sh` or `init.ps1`. The initialization scripts are designed to be idempotent: they refresh the Better-PromptKit directive block without duplicating it or overwriting existing project specifications.

Consumers upgrading from an unreleased snapshot should review changed workflow, protocol, template, and trigger guidance; confirm their `PROMPTKIT.md`, `docs/STATE.md`, and agent-directive customizations; and run their project's own checks after initialization. Existing project-specific specifications remain the consumer's responsibility.

See [`README.md`](../../README.md) and [`docs/ADOPTION-GUIDE.md`](../ADOPTION-GUIDE.md) for the general installation and incremental-adoption procedures.
