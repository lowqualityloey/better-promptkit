- Added `pk:fix` to the directive and canonical routing guidance while preserving `pk:debug` for unknown root causes.
- Added `CONTRIBUTING.md` and JIT specification records for maintainers and contributors.
- Moved detailed release-governance material out of the README’s first-use path while retaining the applicable maintainer boundary.
- Updated `init.ps1` for CRLF/LF marker handling, duplicate and reversed marker rejection, safe regex replacement, UTF-8 preservation, and non-destructive failures.
- Added PowerShell initialization safety regression coverage.

## Migration guidance

Existing Task Records, artifacts, workflows, and initialized projects remain valid; no migration is required.

`pk:fix` is an additional workflow for known findings. It does not replace `pk:debug` for unknown root causes, `pk:review` for review ownership, `pk:commit` for atomic commits, or `pk:ship` for release decisions.

Projects may adopt the new workflow and contribution guidance incrementally.
