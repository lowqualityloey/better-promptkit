# Better-PromptKit v1.1.0 — Lightweight by Default, Rigorous When Risk Demands It

## Highlights

- Canonical Level 0-3 task ceremony with Level 1 as the lightweight default for localized source changes.
- Level 2 readiness for schema, auth, public-contract, multi-component, and architectural-risk work.
- Level 3 release evidence, `pk:ship`, QA, and explicit human authorization.
- Progressive loading, canonical router ownership, cross-platform behavioral checks, LF shell checkout policy, and curated examples.

## What changed

- Clarified the public Level 0-3 task model and escalation boundaries.
- Added onboarding guidance that starts most everyday work at Level 1 without a formal Task Record.
- Preserved Task Record/spec readiness for Level 2 and release evidence for Level 3.
- Added Bash behavioral-contract tests with PowerShell parity and strict validation coverage for the Level 2 SaaS and Level 3 incident examples.
- Enforced LF endings for Bash scripts through `.gitattributes`, including Windows checkouts.
- Added or refreshed README/onboarding guidance, canonical router ownership, progressive-loading guidance, and illustrative Level 1, Level 2, and Level 3 scenarios.

## Migration guidance

Existing Task Records and artifacts remain valid; no migration is required.

Localized bug fixes and small isolated source changes may now follow Level 1 with inline planning and verification rather than requiring `docs/tasks/<task-id>.md`.

Schema/data migrations, authentication/authorization, breaking public contracts, multi-component architecture work, and meaningful risk remain Level 2.

Tags, releases, publication, deployments, and high-impact contract changes remain Level 3 and still require release evidence plus explicit human authorization.

## Compatibility and boundaries

This is an instruction-layer release. Existing records, artifacts, and safety boundaries remain compatible. No application, runtime, dependency, database, or deployment migration is required. The release notes make no unsupported claims about token savings, quality improvements, adoption, or customer outcomes.
